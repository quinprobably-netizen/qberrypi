# qb-panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `qb-panel` turns a panel state into the approved 480 × 320 status page as an RGB565 frame and maps a tap to the blocking switch; `cargo xtask panel-preview` shows any state as a PNG or on the Pi's screen.

**Architecture:** A pure library. `state` and `format` decide every string; `geometry` holds every number of the approved SVG; `draw` paints shapes with `tiny-skia` and text with `ab_glyph` into RGBA and converts to RGB565; `touch` holds the hit test, the press filter, the pause switch and the touch calibration. Time and events come in as arguments. A golden test compares the rendering with the committed reference PNG.

**Tech Stack:** Rust stable, edition 2024. `tiny-skia` (feature `std` only), `ab_glyph` (feature `std` only), JetBrains Mono 2.304 Regular and Bold embedded with `include_bytes!`. Tests: `png`. xtask: `png`, and the `clap`, `anyhow`, `tempfile` and `ssh` it already uses.

**Spec:** `docs/superpowers/specs/2026-11-10-qberrypi-design.md`, sections "Front panel" and "Testing". The approved design is `crates/qb-panel/tests/reference/design-8-reference.svg`; its rendering is `design-8-reference.png` beside it. Where this plan and the SVG disagree on a number, the SVG is right.

**Not in this plan** (the integration plan owns them): opening the framebuffer and the touch device, the clock, the 5-second redraw and the redraw after a tap, and measuring the touch calibration on the real screen.

## Global Constraints

- `crates/qb-panel/src/lib.rs` keeps `#![forbid(unsafe_code)]`.
- No I/O in the library: no `std::fs`, `std::net`, `std::env`, `std::time::Instant` or `SystemTime`, no printing. Fonts are embedded; time arrives as an argument in milliseconds.
- The frame is 480 × 320, RGB565 little-endian, rows from the top, 307,200 bytes.
- Dependencies are pure Rust and are added with `cargo add` (never by editing `Cargo.toml` by hand). The crate must build with `cargo build -p qb-panel --release --target aarch64-unknown-linux-musl`.
- Every public item has a one-line doc comment.
- Before every commit these are clean: `cargo test -p qb-panel`, `cargo clippy --workspace --all-targets`, `cargo fmt --all --check`.
- The repository is public. No real network name, address, host name or anyone's query history in a committed file; names in tests end in `example.com`.
- This plan touches only `crates/qb-panel/` and `Cargo.lock`; Task 7 alone also touches `xtask/`. Other agents are building `qb-wpa2` and `qb-dns` at the same time: if a check reports a problem in another crate, report it and leave that crate alone.
- Stage files by name (never `git add -A` or `git add .`). Every commit message ends with a trailer naming the model that wrote the commit, for example `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Implementers commit and never push.
- The golden test's three limits are not loosened to make it pass. A rendering that misses them is reported with its three numbers.

## Review Focus

1. A blocked name the spec's rule does not fit: no dot within the first line, longer than both lines (a 253-character name, a 32-character hash label), a trailing dot, bytes outside printable ASCII. It must stay inside the window, never panic, and keep its start and its registrable end visible. (Tests in Task 1; glyph coverage in Task 3.)
2. Counters the design's digits do not cover: no queries yet today, blocked above total for a moment (two counters read at different times), six-digit and larger counts. A dash rather than `NaN%`, never above 100 %, and no text reaching its neighbour. (Tests in Tasks 1 and 2.)
3. Meter values outside their range (a 3-second upstream answer, −100 dBm, a 95 °C board): the bar clamps, the number stays true. (Tests in Tasks 2 and 4.)
4. Touch sequences a resistive panel really produces: a press that starts outside and slides in, one that leaves and returns, a release that never arrives, a tap at the millisecond the pause ends. No toggle for the first three; a new pause for the last. (Tests in Task 6.)
5. `panel-preview --push` to a Pi whose screen is absent or set to another rotation or depth: refuse with the reason, write nothing, never fall back to another framebuffer. (Tests in Task 7.)

```rust
// state.rs — all four types derive Debug, Clone, PartialEq, Eq; PanelState and Blocking also Default
pub struct PanelState {
    pub blocked_today: Option<u32>, pub total_today: Option<u32>,
    pub upstream_ms: Option<u16>, pub wifi_dbm: Option<i8>, pub board_c: Option<i8>,
    pub latest: Option<LatestBlocked>, pub blocking: Blocking,
}
pub struct LatestBlocked { pub name: String, pub time: Option<TimeOfDay>, pub count_day: u32 }
pub struct TimeOfDay { pub hour: u8, pub minute: u8 }          // also Copy
pub enum Blocking { #[default] On, Paused { left_secs: u16 } } // also Copy
impl PanelState {
    pub fn reference() -> Self;                      // the values in the approved design
    pub fn blocked_fraction(&self) -> Option<f32>;   // None if a counter is unknown or total is 0; else min(blocked, total) / total
}
// format.rs
pub const DASH: &str = "\u{2014}";                   // an unknown value: an em dash alone, no unit
pub fn count(n: u32) -> String;
pub fn percent(fraction: Option<f32>) -> String;
pub fn latency(ms: Option<u16>) -> String;
pub fn signal(dbm: Option<i8>) -> String;
pub fn temperature(c: Option<i8>) -> String;
pub fn time_line(time: Option<TimeOfDay>) -> String;
pub fn day_line(count_day: u32) -> String;
pub fn footer(blocked: Option<u32>, total: Option<u32>) -> String;
pub fn countdown(left_secs: u16) -> String;
pub fn name_lines(name: &str, cap1: usize, cap2: usize) -> (String, Option<String>);
```

`PanelState::default()` is the state at boot: everything unknown, blocking on. The panel's labels (`Upstream`, `Wi-Fi`, `Board`, `blocked`, `Blocking`, `Paused`) are fixed; the state carries no label text, so no label can grow.

Rules:

| Function | Rule |
|---|---|
| `count` | below 1,000,000: digits with `,` every three (`10,818`). Below 1,000,000,000: millions with one decimal, cut not rounded, and `M` (`1.9M`). Above: the same with `B` (`4.2B`). Never longer than 7 characters. |
| `percent` | `None` → `DASH`. Otherwise `round(fraction × 100)` and `%`. |
| `latency`, `signal`, `temperature` | `8 ms` (through `count`), `-63 dBm`, `51 °C` (ASCII hyphen-minus, one space before the unit); `None` → `DASH`. |
| `time_line` | `blocked 10:20`, 24-hour, both parts two digits. `None`, an hour above 23 or a minute above 59 → `blocked —`. |
| `day_line` | `count(n)` + ` in a day`. |
| `footer` | `count(blocked)` + ` of ` + `count(total)` + ` today`; either unknown → `DASH`. At most 24 characters. |
| `countdown` | `m:ss` of `min(left_secs, 599)`: `4:59`, `0:07`. |

`name_lines`, lengths counted in characters:

1. Remove one trailing `.`. Replace every character outside `'!'..='~'` with `?` (a DNS name is ASCII on the wire; this keeps one advance per character true). Nothing left → `(DASH, None)`.
2. If the name is no longer than `min(cap1, cap2)`: one line.
3. Otherwise break at the last `.` whose index `p` satisfies `1 <= p <= cap1`: line 1 is the text before it, the rest starts with that dot (the design's `tracking-intake.logs` / `.example.com`). With no such dot, line 1 is the first `cap1` characters and the rest follows with no hyphen.
4. If the rest is no longer than `cap2` it is line 2. Otherwise line 2 is `…` (U+2026) followed by the last `cap2 − 1` characters of the rest: the middle of the name is dropped, its start and its registrable end stay.

Meter ranges, each chosen so the design's own bar comes out (20, 113 and 112 pixels wide):

- **Upstream 0–100 ms.** A resolver on a home line answers in 5–40 ms; 100 ms is where a page load starts to feel it, so a full bar means slow.
- **Wi-Fi −90 to −30 dBm.** About where the Pi's radio loses the link, to about the strongest reading beside an access point.
- **Board 20–90 °C.** Room temperature to just above the 85 °C at which the firmware throttles hard.

`name_capacity(n)` is how many 22 px characters fit left of a right-hand text of `n` 15 px characters: `floor((LATEST_TIME.x − NAME_LINE_1.x − NAME_GAP − n × 15 × ADVANCE) / (22 × ADVANCE))`, computed in integer tenths of a pixel as `(4200 − 90 × n) / 132`, zero if that would be negative.

**Files:**

What is drawn, in this order (later covers earlier), every shape anti-aliased:

1. The whole frame `BLACK`.
2. Dial track: the arc from 135° over 270°, radius 80, stroke `TRACK` 16, round caps.
3. If `blocked_fraction()` is known: the arc from 135° to `dial_end_deg(f)` (at least `DIAL_MIN_SWEEP_DEG` long), stroked `GLOW` 24 and then `ACCENT` 16, round caps.
4. The disc: fill `DISC`, then a 1 px `TRACK` outline.
5. If the fraction is known: the tick from `dial_point(TICK_R0, end)` to `dial_point(TICK_R1, end)`, stroke `ACCENT` 4, round caps.
6. `percent(..)` in `PERCENT` (in `PERCENT_WIDE` when it has four characters); `blocked` in `DIAL_LABEL`.
7. For rows 0–2 (`Upstream`/`latency`/`latency_fraction`, `Wi-Fi`/`signal`/`signal_fraction`, `Board`/`temperature`/`temperature_fraction`): the label, the value, `meter_track(row)` filled `TRACK`, and if the value is known `meter_fill(row, fraction)` filled `ACCENT`.
8. `WINDOW_BOX` filled `WINDOW` with a 1 px `TRACK` outline. With no latest name: `DASH` in `NAME_SINGLE` and nothing else. Otherwise `time_line` in `LATEST_TIME`, `day_line` in `LATEST_COUNT`, and `name_lines(name, name_capacity(time_line.chars().count()), name_capacity(day_line.chars().count()))`: one line goes in `NAME_SINGLE`, two in `NAME_LINE_1` and `NAME_LINE_2`.
9. `SWITCH_BOX` filled `DISC` with a 1 px `TRACK` outline. On: `KNOB_ON` filled `ACCENT`, `on` in `KNOB_ON_TEXT`, `Blocking` in `SWITCH_LABEL`. Paused: `KNOB_PAUSED` filled `TRACK`, `countdown(left_secs)` in `KNOB_PAUSED_TEXT`, `Paused` in `SWITCH_LABEL`.
10. `footer(..)` in `FOOTER`.

`rgba_to_rgb565` rounds each channel to the nearest level, `(r × 31 + 127) / 255`, `(g × 63 + 127) / 255`, `(b × 31 + 127) / 255`, packs `r << 11 | g << 5 | b` and writes the low byte first. No dithering: the page is flat colour and text.

The metric, and why it has three parts. librsvg and this crate rasterise edges differently, so equality is the wrong test; each limit catches what the other two let through:

| Part | Definition | Limit | Prototype | Catches |
|---|---|---|---|---|
| `mean_abs` | mean of \|a − b\| over the R, G, B bytes of all pixels | 0.40 | 0.196 | a faint error everywhere (a ground that is not quite black) |
| `outliers` | share of pixels with any channel differing by more than 48 | 0.0003 (46 pixels) | 0.0001 (16 pixels) | a small high-contrast error (a label in the wrong grey, a missing tick) |
| `worst_tile` | the frame in 600 tiles of 16 × 16; the largest per-tile `mean_abs` | 8.0 | 4.1 | an error in one place (an element moved, missing or in another hue) |

The prototype's worst tile holds the colon of `10:20`: Pango applies the font's contextual alternate that raises a colon between digits, and this crate does no shaping. That difference is accepted.

The reference was rendered by librsvg 2.63.3 from the SVG with the JetBrainsMono Nerd Font installed (the SVG's font list falls through to it). ### Task 6: Touch: hit test, press filter, pause switch, calibration

**Files:**
- Create: `crates/qb-panel/src/touch.rs`
- Modify: `crates/qb-panel/src/lib.rs`

**Interfaces:**
- Consumes: `geometry::SWITCH_TARGET` (Task 2); `state::Blocking` (Task 1).
- Produces:

```rust
pub enum Control { BlockingSwitch }                                   // Debug, Clone, Copy, PartialEq, Eq
pub fn hit(x: u16, y: u16) -> Option<Control>;                        // screen coordinates

pub enum TouchEvent { Down { x: u16, y: u16 }, Move { x: u16, y: u16 }, Up }   // Debug, Clone, Copy, PartialEq, Eq
pub const MIN_PRESS_MS: u64 = 50;
pub struct TapTracker { /* private */ }                               // Default
impl TapTracker { pub fn feed(&mut self, at_ms: u64, event: TouchEvent) -> Option<Control>; }

pub const PAUSE_MS: u64 = 300_000;
pub enum Switch { #[default] On, PausedUntil(u64) }                   // Debug, Clone, Copy, PartialEq, Eq, Default
impl Switch {
    pub fn tapped(self, now_ms: u64) -> Switch;
    pub fn blocking(self, now_ms: u64) -> Blocking;
}

pub struct Calibration { pub swap_xy: bool, pub left: u16, pub right: u16, pub top: u16, pub bottom: u16 }
impl Calibration { pub const NOMINAL: Calibration = Calibration { swap_xy: false, left: 200, right: 3900, top: 200, bottom: 3900 }; }
pub fn to_screen(cal: &Calibration, raw_x: u16, raw_y: u16) -> (u16, u16);
```

Times are milliseconds on any clock that does not jump; the caller owns it.

- **`TapTracker`.** `Down` starts a press on `hit(x, y)`, which may be nothing. A `Move` whose `hit` differs from the press's control spoils the press for good. `Up` returns the control if the press has one, is unspoiled and began at least `MIN_PRESS_MS` earlier (a clock that went backwards counts as 0 ms); then the tracker is idle. `Down` during a press starts over; `Up` or `Move` while idle does nothing. There is no upper limit on a press.
- **`Switch`.** A pause is over once `now_ms >= until`. `tapped`: on (or a pause that is over) → `PausedUntil(now_ms + PAUSE_MS)`; a running pause → `On`. `blocking`: `On`, or `Paused { left_secs }` with the milliseconds left rounded up to whole seconds (at most `u16::MAX`), so it reads `5:00` at the tap and `0:01` in the last second. The switch lives in memory only, so a pause never outlives a reboot.
- **`to_screen`.** `raw_x` and `raw_y` are the `ABS_X` and `ABS_Y` readings of the `ads7846` driver. With `swap_xy` they are exchanged first. Then `x = round((h − left) × 479 / (right − left))` and `y = round((v − top) × 319 / (bottom − top))`, in signed arithmetic, each clamped to the screen; `left > right` or `top > bottom` is an axis that runs backwards; equal ends give 0.
- **The 90° rotation.** The `piscreen` overlay marks the touch axes as swapped, which lines `ABS_X` up with the panel's long side, and with `rotate=90` the display driver only exchanges rows and columns (address mode `0x20`). So on this screen `ABS_X` runs along the 480-pixel side and `swap_xy` is `false`. Which way each axis counts depends on the individual panel. `NOMINAL` is therefore unmeasured: the integration plan replaces its four readings with ones taken by touching the corners of the real screen.

No `sudo`: on Raspberry Pi OS the user is in the `video` group, which owns the framebuffer devices.

The `FindScreen` script looks at every `<sys_graphics>/fb*/name` and takes the one whose content is `fb_ili9486`, never a number it assumed.
