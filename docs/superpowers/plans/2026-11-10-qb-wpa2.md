# qb-wpa2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give qberrypi the supplicant side of WPA2-PSK as a pure crate: received EAPOL-Key frames go in, the frames to send and the keys to install come out.

**Architecture:** Six small modules of pure functions (secret container, PMK, PTK, EAPOL-Key frame, key data, RSN element) under one state machine, `Supplicant`, which owns no socket, clock or random source. The caller hands it each received frame and a closure that yields a nonce; it returns the reply frame and any key to install, or a typed error and no change. Every primitive is checked against a published vector and against a second implementation; the state machine is checked byte for byte against a handshake built with Python and OpenSSL and against a captured real one.

**Tech Stack:** Rust stable, edition 2024. RustCrypto `pbkdf2` 0.13, `hmac` 0.13, `sha1` 0.11, `aes-kw` 0.3; `zeroize` 1.9; `subtle` 2.6; for tests `hex-literal` 1.1. These are the versions `cargo add` selected on 2026-11-10; with them `pbkdf2::pbkdf2_hmac::<sha1::Sha1>(password, salt, 4096, &mut out)`, `hmac::Hmac::<Sha1>::new_from_slice(key)` (traits `hmac::KeyInit`, `hmac::Mac`) and `aes_kw::KwAes128::new(kek.into())` with `unwrap_key(wrapped, &mut out)` / `wrap_key(plain, &mut out)` compile and pass the vectors below, on the host and for `aarch64-unknown-linux-musl`. Python 3's standard library, `wpa_passphrase` and the `openssl` command line are test oracles on the development machine only.

**Spec:** `docs/superpowers/specs/2026-11-10-qberrypi-design.md` — sections "Wi-Fi", "Testing", "Non-goals for version 1", "Repository layout".

## Global Constraints

- Scope: WPA2-PSK, CCMP as pairwise and as group cipher, key descriptor version 2 (HMAC-SHA1 MIC, AES key wrap). No protected management frames, no WPA3, no TKIP, no enterprise Wi-Fi.
- `#![forbid(unsafe_code)]` stays at the top of `src/lib.rs`.
- No I/O of any kind: no sockets, files, clock, threads, environment or random source. No `println!`, `eprintln!`, `dbg!` and no logging. Nonces come from the caller.
- Secrets — passphrase, PMK, KCK, KEK, TK, GTK, unwrapped key data — are wiped on drop and never appear in `Debug`, `Display` or any error value. Errors carry no bytes of any frame or key.
- No decode function may panic on any input: outside tests, no `unwrap`, `expect`, indexing or slicing whose success depends on input bytes or lengths.
- Every public item has a one-line doc comment; tests sit at the bottom of the file they test, or in `tests/` when they use only the public interface (the house style of `crates/qberrypi/src/config.rs`).
- Dependencies: the crates named under Tech Stack, added with `cargo add -p qb-wpa2`. No C code, no build script. The crate must build for `aarch64-unknown-linux-musl`.
- Gates, all clean before every commit: `cargo test -p qb-wpa2`, `cargo clippy --workspace --all-targets` (no warnings), `cargo fmt --all --check`.
- Only `crates/qb-wpa2/` and `Cargo.lock` change. Other agents are building `qb-dns` and `qb-panel` in other worktrees at the same time; this work happens in the worktree and branch the session lead created for it.
- The repository is public. No real network name, passphrase or address in any committed file: test data is the IEEE and RFC sample values and the two published sample captures this plan names, nothing else.
- Files are staged by name (`git add <path>…`, never `-A` or `.`). Every commit message ends with a `Co-Authored-By:` trailer naming the model that wrote the commit, for example `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Implementers commit and never push.
- Downloaded files (Task 9) are untrusted data: each in its own empty directory outside the repository, read only by a script kept in another directory and run with `python3 -I`; nothing from them is executed and the files are not committed.

## Review Focus

1. The passphrase in `qberrypi.toml` is wrong. The access point then never sends message 3: it repeats message 1 and disconnects. The state machine must stay in `AwaitingMessage3`, reuse its SNonce and never panic, so the caller can log "passphrase may be wrong" when the link drops in that phase. (Test in Task 7.)
2. Message 4 is lost and the access point repeats message 3 after the keys were installed. The reply must be sent again and the same keys must not be handed out a second time: installing a key twice resets its packet counter, which is the KRACK attack. (Test in Task 8.)
3. Real access points pad the key data in three ways: `dd` then zeros, a lone `dd`, and two zero bytes that are not in the standard. All must parse. (Test in Task 5.)
4. A network with the right name but outside the scope — mixed WPA/WPA2 with a TKIP group cipher, or one that requires protected management frames. It must be refused before association with an error that names the reason, not fail later inside message 3. (Tests in Tasks 6, 7 and 9.)
5. A frame arrives with bytes after its declared length (link-layer padding) or with a body longer than its key data. The MIC covers the declared length only and the frame must be accepted. (Tests in Tasks 4 and 7.)

## Oracles

Each primitive has two checks that do not pass through this crate's own code. All values were confirmed on the development machine on 2026-11-10; none is taken from memory alone.

| What | Published vector | Second, independent check |
|---|---|---|
| Passphrase to PMK | IEEE Std 802.11-2016 Annex J.4.2, test cases 1–3 | `wpa_passphrase` (wpa_supplicant 2.12) and Python `hashlib.pbkdf2_hmac` print the same three values |
| PRF | IEEE Std 802.11-2016 Annex J.3.2 and J.6.5 | Python `hmac` reproduces all seven |
| PTK | IEEE Std 802.11-2016 Annex J.7.1 (inputs) and J.7.2 (CCMP keys) | Python `hmac`; the MICs of two captured handshakes verify under keys derived the same way |
| AES key unwrap | RFC 3394 section 4.1 | `openssl enc -id-aes128-wrap` (OpenSSL 3.6.5): it reproduces the RFC vector, wrapped the reference key data (24 and 48 bytes) and unwraps the two captures' (48 and 72 bytes) |
| EAPOL-Key layout and MIC | — | frames built by Python (`tests/fixtures/reference_handshake.py`); frames of two captures |
| Whole four-way handshake | — | `wpa2-psk-linksys.cap`: this crate must reproduce a real station's messages 2 and 4 byte for byte |
| Group-key handshake | — | reference frames `G1`, `G2` built by Python and OpenSSL |

The IEEE values were read from the transcriptions in Fuchsia's `wlan-rsn` crate (`src/prf.rs`, `src/key/ptk.rs`, `src/auth/psk.rs`), which cites the annex clause for each, and every one was recomputed here with Python. RFC 3394 was read at `https://www.rfc-editor.org/rfc/rfc3394.txt`.

## Decisions the spec leaves open

1. Replies carry 802.1X protocol version 1 and key length 0. That is what `wpa_supplicant` sends and what the station in `wpa2-psk-linksys.cap` sent.
2. The supplicant's own RSN element is a parameter. Message 2 must repeat the element of the association request exactly, and FullMAC firmware may alter what it is given: the caller passes the constant `SUPPLICANT_RSNE` unless the kernel reports that something else was sent.
3. The group cipher must be CCMP. A mixed WPA/WPA2 network (TKIP group cipher) is refused. A WPA2/WPA3 transition network is accepted through its PSK suite; a network that requires protected management frames is refused.
4. A key is handed to the caller once. A repeated message 3 or group message 1 is answered again, without the key.
5. Message 1 on an established link starts a second handshake beside the installed keys, which stay valid until its message 3 verifies. Message 1 has no MIC, so a forged one must not be able to drop a working link.
6. One SNonce per handshake: repeated message 1s reuse it, as `wpa_supplicant` does, so a message 3 that answers an earlier message 2 still verifies.
7. The replay counter is taken only from frames whose MIC verified, never from message 1 (IEEE 802.11-2016 12.7.2).
8. Message 3 must have the Install and Encrypted bits, key length 16, the advertised RSN element and a GTK. `wpa_supplicant` does not insist on Install; this crate does, so that a message 3 which does not ask for the key to be installed never completes a handshake.
9. A second RSN element, RSNXE or GTK in one key data field is refused rather than picked from.
10. There is no RSN element builder: qberrypi sends exactly one element, so it is a constant with a test.
11. The no-panic check is a deterministic sweep (every truncation, every single-byte change, a fixed-seed random stream), not `proptest`: the frame formats break at length boundaries, which the sweep covers exhaustively, and it adds no dependency.
12. The reference handshake is generated by a Python script committed beside the fixture. Python, because an oracle written with the same Rust crates would not be independent.
13. The capture that drives the state machine comes from the aircrack-ng repository (GPL-2.0); about 500 bytes of its frames become test constants with a citation. Task 9 is separate so the owner can strike it. The Wireshark sample capture `wpa-Induction.pcap`, first considered for that role, is a mixed-mode network with a TKIP group key; it serves as the real network this crate must refuse.

Not in this crate: choosing among access points (5 GHz first), timeouts, retransmission, retry backoff, moving frames, installing keys. Those are the integration plan's.

```python
#!/usr/bin/env python3
"""Reference WPA2-PSK/CCMP handshake, built without any qb-wpa2 code.

HMAC-SHA1 and PBKDF2 come from Python's standard library, the AES key wrap
from the OpenSSL command line. Inputs are the sample values of IEEE Std
802.11-2016 Annex J.4 and J.7 and of RFC 3394. Prints reference.rs:
    python3 -I reference_handshake.py > reference.rs
"""
import hashlib, hmac, os, subprocess, tempfile

H = bytes.fromhex
PMK = hashlib.pbkdf2_hmac("sha1", b"ThisIsAPassword", b"ThisIsASSID", 4096, 32)
AA, SPA = H("a0a1a1a3a4a5"), H("b0b1b2b3b4b5")
ANONCE = H("e0e1e2e3e4e5e6e7e8e9f0f1f2f3f4f5f6f7f8f9fafbfcfdfeff000102030405")
SNONCE = H("c0c1c2c3c4c5c6c7c8c9d0d1d2d3d4d5d6d7d8d9dadbdcdddedfe0e1e2e3e4e5")
RSNE = H("30140100000fac040100000fac040100000fac020000")
GTK1, GTK2 = H("00112233445566778899aabbccddeeff"), H("000102030405060708090a0b0c0d0e0f")
RSC3, RSCG = H("1122334455660000"), H("0a0b0c0d0e0f0000")


def prf(key, label, data, n):
    out = b""
    for i in range((n + 19) // 20):
        out += hmac.new(key, label + b"\0" + data + bytes([i]), hashlib.sha1).digest()
    return out[:n]


def wrap(kek, plain):
    with tempfile.TemporaryDirectory() as d:
        src, dst = os.path.join(d, "in"), os.path.join(d, "out")
        open(src, "wb").write(plain)
        subprocess.run(["openssl", "enc", "-e", "-id-aes128-wrap", "-K", kek.hex(),
                        "-iv", "a6a6a6a6a6a6a6a6", "-in", src, "-out", dst], check=True)
        return open(dst, "rb").read()


def frame(version, info, key_len, counter, nonce, rsc, data, kck=None):
    body = (bytes([2]) + info.to_bytes(2, "big") + key_len.to_bytes(2, "big")
            + counter.to_bytes(8, "big") + nonce + bytes(16) + rsc + bytes(8)
            + bytes(16) + len(data).to_bytes(2, "big") + data)
    f = bytes([version, 3]) + len(body).to_bytes(2, "big") + body
    if kck:
        f = f[:81] + hmac.new(kck, f, hashlib.sha1).digest()[:16] + f[97:]
    return f


def gtk_kde(key_id, gtk):
    return H("dd16000fac01") + bytes([key_id, 0]) + gtk


ptk = prf(PMK, b"Pairwise key expansion",
          min(AA, SPA) + max(AA, SPA) + min(ANONCE, SNONCE) + max(ANONCE, SNONCE), 48)
KCK, KEK, TK = ptk[:16], ptk[16:32], ptk[32:]
Z32, Z8 = bytes(32), bytes(8)
frames = {
    "M1": frame(2, 0x008A, 16, 1, ANONCE, Z8, b""),
    "M2": frame(1, 0x010A, 0, 1, SNONCE, Z8, RSNE, KCK),
    "M3": frame(2, 0x13CA, 16, 2, ANONCE, RSC3, wrap(KEK, RSNE + gtk_kde(1, GTK1) + H("dd00")), KCK),
    "M4": frame(1, 0x030A, 0, 2, Z32, Z8, b"", KCK),
    "G1": frame(2, 0x1382, 0, 5, Z32, RSCG, wrap(KEK, gtk_kde(2, GTK2)), KCK),
    "G2": frame(1, 0x0302, 0, 5, Z32, Z8, b"", KCK),
}
consts = [("PMK", PMK), ("AA", AA), ("SPA", SPA), ("ANONCE", ANONCE), ("SNONCE", SNONCE),
          ("RSNE", RSNE), ("KCK", KCK), ("KEK", KEK), ("TK", TK), ("GTK1", GTK1), ("GTK2", GTK2)]
print("// Generated by reference_handshake.py from IEEE and RFC sample values; do not edit.")
print("#![allow(dead_code)]")
print("use hex_literal::hex;")
for name, value in consts + list(frames.items()):
    print(f'pub const {name}: [u8; {len(value)}] = hex!("{value.hex()}");')
```

The algorithm, from IEEE 802.11-2016 12.7.1.2 and 12.7.1.3:

```
PRF(K, A, B, n)  = first n bytes of  HMAC-SHA1(K, A ‖ 0x00 ‖ B ‖ 0x00) ‖ HMAC-SHA1(K, A ‖ 0x00 ‖ B ‖ 0x01) ‖ …
PTK              = PRF(PMK, "Pairwise key expansion",

KCK = PTK[0..16]   KEK = PTK[16..32]   TK = PTK[32..48]
```

`min` and `max` compare the byte strings as big-endian numbers, which is what `<` on arrays does.


Wire layout, every integer big-endian (IEEE 802.1X-2004 7.5 and IEEE 802.11-2016 12.7.2):

| Offset | Bytes | Field |
|---|---|---|
| 0 | 1 | protocol version (any value accepted) |
| 1 | 1 | packet type, 3 for EAPOL-Key |
| 2 | 2 | body length: everything after these four bytes |
| 4 | 1 | descriptor type, 2 for RSN |
| 5 | 2 | key information |
| 7 | 2 | key length |
| 9 | 8 | replay counter |
| 17 | 32 | nonce |
| 49 | 16 | IV |
| 65 | 8 | RSC |
| 73 | 8 | reserved: ignored on decode, zero on encode |
| 81 | 16 | MIC |
| 97 | 2 | key data length |
| 99 | n | key data |

`decode` checks, in this order: fewer than 4 bytes → `Truncated`; packet type not 3 → `NotKeyFrame`; frame shorter than 4 + body length → `Truncated`; body length under 95 → `BodyTooShort`; descriptor type not 2 → `NotRsnDescriptor`; key data length greater than body length − 95 → `KeyDataOverrun`. Bytes after 4 + body length, and body bytes after the key data, are ignored. `encode` fails with `KeyDataTooLong` above 65 440 bytes of key data.

The MIC is HMAC-SHA1 under the KCK over the first 4 + body length bytes of the frame as received, with bytes 81..97 taken as zero, truncated to 16 bytes. `mic`, `verify_mic` and `sign` apply the first four `decode` checks and never re-encode.

`unwrap_key_data` is RFC 3394 with the default initial value, through `aes_kw::KwAes128`. A length under 24 or not a multiple of 8 is `WrappedLength`, checked before anything is allocated or subtracted; a failed integrity check is `Unwrap`.

`parse_key_data` walks elements of the form id, length, data (IEEE 802.11-2016 12.7.2), with the rules `wpa_supplicant` applies:

1. Stop when fewer than two bytes remain; a single left-over byte is ignored.
2. id `0xdd` with length 0 is padding: stop.
3. An element whose 2 + length exceeds what remains → `Truncated`.
4. id `0x30` is the RSN element, id `0xf4` the RSNXE: keep the whole element.
5. id `0xdd` whose data starts `00 0f ac 01` is the GTK KDE: data = those four bytes, one flags byte (key id in bits 0–1, Tx in bit 2), one reserved byte, the key. The key must be 16 bytes (length byte 22); any other length → `GtkLength`.
6. A second RSN element, RSNXE or GTK KDE → `Duplicate`.
7. Every other element is skipped.

`Display` for the four scope errors is the log line the spec asks for at scan time: `GroupCipherNotCcmp` → "group cipher is not CCMP (mixed WPA/WPA2 network)"; `NoCcmpPairwise` → "CCMP is not offered as pairwise cipher"; `NoPskAkm` → "WPA2-PSK is not offered"; `PmfRequired` → "protected management frames are required". The others get one fixed sentence each.

`parse` (IEEE 802.11-2016 9.4.2.25): under two bytes → `Truncated`; id not `0x30` → `NotRsne`; slice length not 2 + length byte → `Length`; then version, a little-endian `u16` that must be 1 (`Version`; missing → `Truncated`). After the version the element may end before any of these, in order, and an absent field takes its default: group suite (4 bytes; CCMP), pairwise count (`u16` LE) and that many suites (`[CCMP]`), AKM count and suites (`[00 0f ac 01]`), capabilities (`u16` LE; 0). Ending inside a field → `Truncated`; a count of 0 → `EmptySuiteList`. Whatever follows the capabilities (PMKIDs, group management cipher) is ignored.

`check_access_point`, first failure wins: group is not CCMP → `GroupCipherNotCcmp`; pairwise list lacks CCMP → `NoCcmpPairwise`; AKM list lacks PSK → `NoPskAkm`; `CAP_MFPR` set → `PmfRequired`. `check_supplicant`: group CCMP, pairwise exactly `[CCMP]`, AKMs exactly `[PSK]`, neither `CAP_MFPR` nor `CAP_MFPC`; otherwise `NotWpa2PskCcmp`.

`Supplicant::new` refuses what is outside the scope: `Rsne::parse(&ap_rsne)` then `check_access_point()` → `ApRsne(e)`; `Rsne::parse(&own_rsne)` then `check_supplicant()` → `OwnRsne(e)`.

State: an optional pending handshake (ANonce, SNonce, the PTK derived from them), an optional established PTK with its ANonce, and the replay counter of the last frame whose MIC verified. `phase()` follows from the two options: neither → `AwaitingMessage1`; pending only → `AwaitingMessage3`; established only → `Established`; both → `Rekeying`.

`handle` applies these checks in order and returns at the first failure. **On any error nothing in `self` has changed**: work on locals and assign at the end.

1. `EapolKey::decode` → `Frame(e)`.
2. `info.version()` is not 2 → `KeyVersion`.
3. Any of `REQUEST`, `ERROR`, `SMK` set, or `ACK` clear → `UnexpectedFlags`.
4. The frame is **message 1** if `PAIRWISE` is set and `MIC` and `INSTALL` are clear; **message 3** if `PAIRWISE` and `MIC` are set; a **group message** if `PAIRWISE` is clear and `MIC` is set; anything else → `UnexpectedFlags`.
5. A MIC-verified counter is on record and the frame's replay counter is not greater → `Replay`.
6. In this task, a group message, and any frame once the phase is `Established`, → `WrongPhase`. Task 8 replaces this rule.

Message 1:

7. SNonce is the pending handshake's if there is one; otherwise call `snonce()`. The closure is called at no other time.
8. Derive the PTK from the frame's nonce and the SNonce; it and the two nonces become the pending handshake, replacing any earlier one.
9. Reply `Message2`: protocol version 1, key information `0x010a`, key length 0, the frame's replay counter, nonce = SNonce, key data = `own_rsne`, every other field zero, signed with the pending KCK. No keys.

Message 3:

10. No pending handshake → `WrongPhase`. The frame's nonce differs from the pending ANonce → `AnonceMismatch`.
11. `verify_mic` under the pending KCK is not `Ok(true)` → `BadMic`.
12. `INSTALL` clear → `InstallNotSet`; `ENCRYPTED` clear → `NotEncrypted`; key length not 16 → `KeyLength`.
13. `unwrap_key_data` under the pending KEK, then `parse_key_data` → `KeyData(e)`.
14. The RSN element is absent or not byte-equal to `ap_rsne` → `RsneMismatch`. No GTK → `GtkMissing`.
15. Accept: the pending handshake becomes the established keys; the frame's counter goes on record. Reply `Message4`: protocol version 1, key information `0x010a` plus the `SECURE` bit as message 3 had it (so `0x030a` in practice), key length 0, the frame's replay counter, no key data, every other field zero, signed with the new KCK. `tk` is the new TK; `gtk` has the KDE's key id, Tx bit and key and the first six bytes of the frame's RSC; `warning` is `RsnxeMismatch` when `rsnxe_matches(ap_rsnxe, key data's RSNXE)` is false.

Keys are handed out once. The supplicant remembers the last TK and the last GTK (key id and key) it returned. A reply's `tk` is `None` when the TK equals the remembered one, and its `gtk` is `None` when key id and key equal the remembered ones. Everything else about the reply is unchanged.

Message 1 while established: rules 7–9 as they are. The established keys are untouched; the phase becomes `Rekeying`. Because nothing is pending right after a handshake completes, the first such message 1 asks the caller for a fresh SNonce.

Message 3, replacing rules 10 and 11: the candidates are the pending handshake, then the established keys. Neither exists → `WrongPhase`. Drop candidates whose ANonce differs from the frame's nonce; none left → `AnonceMismatch`. Use the first remaining candidate whose KCK verifies the MIC; none → `BadMic`. Rules 12–14 follow with that candidate's KEK. On acceptance of the pending candidate it becomes the established keys and the pending handshake is gone; on acceptance of the established candidate (a repeated message 3) a pending handshake, if any, stays. `Message4` is signed with the accepted candidate's KCK.

Group message (`PAIRWISE` clear, `MIC` set), after rules 1–5:

16. Not established → `WrongPhase`.
17. `verify_mic` under the established KCK is not `Ok(true)` → `BadMic`. A pending handshake's keys are never tried.
18. `ENCRYPTED` clear → `NotEncrypted`. Unwrap and parse under the established KEK → `KeyData(e)`. No GTK → `GtkMissing`. The key length field is not checked (access points send 0 or 16).
19. Accept: the frame's counter goes on record; the phase does not change. Reply `GroupMessage2`: protocol version 1, key information `0x0302`, key length 0, the frame's replay counter, no key data, every other field zero, signed with the established KCK. `gtk` as in rule 15, subject to the hand-out-once rule; `tk` is `None`.

```python
"""List RSN elements and EAPOL frames of an 802.11 pcap: python3 -I list_eapol.py FILE"""
import struct, sys

data = open(sys.argv[1], "rb").read()
assert data[:4] == b"\xd4\xc3\xb2\xa1", "not a little-endian pcap"
radiotap = struct.unpack("<I", data[20:24])[0] == 127
pos, number, seen = 24, 0, set()
while pos + 16 <= len(data):
    size = struct.unpack("<I", data[pos + 8:pos + 12])[0]
    pkt, pos, number = data[pos + 16:pos + 16 + size], pos + 16 + size, number + 1
    if radiotap:
        pkt = pkt[struct.unpack("<H", pkt[2:4])[0]:]
    kind = pkt[0] & 0xFC if pkt else 0xFF
    fixed = {0x80: 36, 0x50: 36, 0x00: 28}.get(kind)  # beacon, probe response, association request
    body = pkt[fixed:] if fixed else b""
    while len(body) >= 2:
        if body[0] == 0x30 and body[:2 + body[1]] not in seen:
            seen.add(body[:2 + body[1]])
            print(number, "rsne", body[:2 + body[1]].hex())
        body = body[2 + body[1]:]
    at = pkt.find(b"\xaa\xaa\x03\x00\x00\x00\x88\x8e")
    if kind & 0x0C == 0x08 and 0 < at <= 32:
        eapol = pkt[at + 8:]
        print(number, "eapol", eapol[:4 + int.from_bytes(eapol[2:4], "big")].hex())
```
