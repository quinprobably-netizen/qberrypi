# Milestone 0 (Boot) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command deploys qberrypi beside Raspberry Pi OS, the Pi boots once into a Rust PID 1 that shows a banner, loads the Wi-Fi driver, writes its log to the card and returns to Raspberry Pi OS by itself.

**Architecture:** A cargo workspace with the `qberrypi` executable (static, `aarch64-unknown-linux-musl`, synchronous in this milestone) and an `xtask` host tool that fetches pinned Raspberry Pi packages, packs the initramfs, runs the result under QEMU, and deploys it over SSH. All logic that can run on the development machine is in plain functions tested there; the few real syscalls sit in one file and are proven by the QEMU test.

**Tech Stack:** Rust stable, edition 2024. Executable: `serde`, `toml`, `log`, `rustix`, `libc`. xtask: `clap`, `anyhow`, `ureq`, `sha2`, `ar`, `tar`, `zstd`, `fatfs`, `tempfile`. System tools used by xtask only: `xz`, `ssh`, `scp`, `qemu-system-aarch64`.

**Spec:** `docs/superpowers/specs/2026-11-10-qberrypi-design.md`

## Global Constraints

- Board: Raspberry Pi 3 Model B+ only. Kernel release pinned to `6.18.60+rpt-rpi-v8`.
- The initramfs contains exactly one executable, `/init`. The executable never runs another program.
- qberrypi never mounts or writes `/dev/mmcblk0p2`.
- The boot partition is written only when `debug.one_shot` or `debug.log_to_sd` is on, or on a fatal error before the configuration was parsed. Every write is followed by a sync and an unmount.
- The Wi-Fi passphrase and PMK never appear in a log line, an error message or `Debug` output.
- Nothing from the fetched packages is committed. `vendor-cache/`, `out/` and `qberrypi.toml` stay git-ignored.
- The repository is public. No real network name, address, host name or key in any committed file; examples use `192.0.2.0/24`.
- `unsafe` is allowed only in `crates/qberrypi/src/sys.rs`.
- Every commit message ends with the line `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Task implementers commit but do not push; the session lead pushes after each task's review.

## Review Focus

1. `config.pios.txt` is missing, empty, or itself selects qberrypi: restoring must leave `config.txt` untouched and say why; a second deploy must never overwrite the backup with qberrypi's own config. (Tests in Tasks 4 and 10.)
2. `qberrypi.toml` is unreadable or not valid TOML: the Pi must still return to Raspberry Pi OS instead of restarting into qberrypi forever. (Tests in Tasks 6 and 9.)
3. A configuration error or log line echoes the passphrase. (Tests in Tasks 2 and 9.)
4. `/dev/mmcblk0p1` appears late or never: wait a bounded time, then fail with a message that names the device. (Test in Task 4.)
5. `log.txt` grows on every one-shot boot: it is capped at 1 MiB. (Test in Task 4.)

LED writes: `Serving` → `[("trigger","heartbeat")]`; `Joining` → `[("trigger","timer"),("delay_on","100"),("delay_off","100")]`; `Fatal` → `[("trigger","default-on")]`.

`init::run` does exactly this, in order:

1. `mount_pseudo`; `logbuf::install` on `/dev/console`; log `banner()`.
2. `clock_at_least(BUILD_EPOCH)`.
3. `Watchdog::open(15)`; failure is a warning, not fatal.
4. `wait_for_path(BOOT_DEV, 10 s)`, else fatal `"boot partition /dev/mmcblk0p1 did not appear"`. Mount read-only, `read_config_text`, unmount, `config::parse`. A read or parse failure is fatal.
5. If `debug.one_shot`: mount read-write, `restore_pios_config`, log `config.txt: {outcome:?}` (for example `config.txt: Restored`), sync, unmount.
6. `set_hostname`; `register_module_helper("/init")`; `modules::load` for `cfg80211` with params `ieee80211_regdom={country}`, then for `brcmfmac` with none. Any failure is fatal.
7. `led::set(Serving)`. If `kernel_arg("qberrypi.selftest")`, open and drop one `AF_INET6` datagram socket, ignoring the result, so the kernel calls the module helper.
8. Wait up to 20 s for `/sys/class/net/wlan0`. Log `wlan0: present` or `wlan0: absent`, and `brcmfmac_cyw: loaded` or `brcmfmac_cyw: not loaded` from `/sys/module/brcmfmac_cyw`. Log every line from `kmsg::read_all("/dev/kmsg")` as `kernel: {text}`.
9. If `debug.log_to_sd`: mount read-write, `append_log` with a header line `==== boot, build {BUILD_EPOCH} ====` and `take_unsaved()`, sync, unmount.
10. Loop: pet the watchdog every 5 s. When `debug.return_after_secs > 0` and that long has passed since step 1, log `returning`, repeat step 9, `reboot()`.

The watchdog timeout is 15 s and the waits in steps 4 and 8 are longer or close to it, so every wait in `init` goes through one helper that pets the watchdog at least every 5 s while it polls.

`fatal(msg)`: log at error level; `led::set(Fatal)`; if `restore_on_fatal(cfg)`, mount read-write, `restore_pios_config`, `append_log`, sync, unmount, ignoring errors; sleep 5 s; `reboot()`. A panic hook calls `fatal` with the panic message.

`main.rs`: if `std::process::id() == 1`, `init::run()`. Otherwise read `MODULE_LIST`, call `modhelper::run` with `sys::finit_module` and `/dev/kmsg`, and exit with its result.
