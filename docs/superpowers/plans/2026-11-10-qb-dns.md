# qb-dns Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `qb-dns` turns blocklist text into a compact block set, and turns each DNS packet plus the current time into a decision — blocked, answered locally, cached, stale-and-refresh, or forward — with the reply bytes and the counters the front panel and status page show.

**Architecture:** No sockets, clock or threads. `BlockSetBuilder` parses list text into sorted name tables (exact, suffix, allow). `Resolver` owns the block set, a least-recently-used cache of upstream answers, the pause deadline and the statistics; the caller hands it client packets and upstream packets with a `Now`, and carries out the `Action` it returns. `hickory-proto` parses and encodes every message except two 12-byte error headers.

**Tech Stack:** Rust stable, edition 2024. One dependency: `hickory-proto` 0.26 (default features, pure Rust). Tests use a small seeded generator of their own, so no property-testing crate is added.

**Spec:** `docs/superpowers/specs/2026-11-10-qberrypi-design.md` — sections DNS, Blocklists, Status, Front panel, Configuration, Non-goals, Testing.

## Global Constraints

- `#![forbid(unsafe_code)]` stays the first attribute of `src/lib.rs`. No `unsafe` in tests either.
- No I/O in the library: nothing under `src/` opens a file or socket, reads a clock, spawns a thread, sleeps or prints. Time arrives as `Now`, list text as `&[u8]`. The only file reading is in `tests/real_lists.rs`.
- Arbitrary bytes never panic: `normalize`, `parse_list`, `BlockSetBuilder::add_list`, `Resolver::handle_query` and `Resolver::handle_upstream` return normally for any input, and each has a seeded fuzz-style test. No `unwrap`, `expect` or unchecked indexing on input-derived data outside tests.
- Every public item has a one-line doc comment; `#![warn(missing_docs)]` is on.
- Clean before every commit, with no warnings: `cargo test -p qb-dns`, `cargo clippy --workspace --all-targets`, `cargo fmt --all --check`.
- Must build for the Pi: `cargo build -p qb-dns --target aarch64-unknown-linux-musl`. Dependencies are pure Rust and are added with `cargo add`.
- Spec values: cache 10,000 entries, least recently used evicted; stale answers served for under one hour; last 50,000 queries kept; blocked names answer `0.0.0.0` (A), `::` (AAAA), empty success (other types).
- The repository is public. No real network name, address or query history in any committed file. Names are `example.com`, `example.net`, `example.org`, `*.test`, `*.invalid`; addresses come from `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`. One exception, stated here: the three captured answers in `src/testutil.rs` hold the public records of `example.com` and `invalid.` exactly as 9.9.9.9 served them.
- Nothing from a downloaded list is committed. HaGeZi is GPL-3.0, and the StevenBlack file merges sources under CC BY 3.0 and CC BY-SA 4.0, so both committed fixtures are synthetic. `vendor-cache/` stays git-ignored.
- Touch only `crates/qb-dns/` and `Cargo.lock`. Other agents are building other crates in other worktrees.
- Git: stage files by name (never `git add -A` or `git add .`). Every commit message ends with a `Co-Authored-By:` trailer naming the model that wrote the commit, for example `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Never push.

## Review Focus

1. A list URL returns something that is not a blocklist — an HTML error page, or a browser adblock list with cosmetic rules such as `example.com##.ad`: no name may be blocked by accident, and the counts must show zero rules so the caller can keep the old set. (Test in Task 2.)
2. A query name whose bytes only look like a listed name — one label containing a dot: it must not match the rule for the dotted name, and must not share a cache entry with it. (Test in Task 5.)
3. An upstream packet that is well formed but answers another question, or is itself a query: it must change neither the cache nor the client's answer. (Test in Task 11.)
4. The wall clock steps — it does at every boot, from the image build time to SNTP time, and it can step back: "today" resets without underflow, while cache lifetimes, the pause and the 24-hour count, which run on the monotonic clock, do not move. (Tests in Tasks 8, 9 and 10.)
5. A blocked name is forwarded and cached while blocking is paused: when the pause ends it must be blocked again on the next query, although a fresh cache entry exists. (Test in Task 11.)

## Decisions the spec leaves open

Each row is pinned by a test in the task named. Tasks refer to rows by their subject.

| Subject | Decision | Task |
|---|---|---|
| Where lists are parsed | Here, not in the main crate's `lists` module, which keeps fetching and the snapshot. | 2 |
| List line format | Detected per line; the configuration has no format field. Plain one-domain-per-line lists are not read: each such line counts as unsupported. | 2 |
| Valid name | Lower-cased, one trailing dot dropped, 1–253 bytes, labels of 1–63 bytes from `a-z 0-9 - _`, last label not all digits. Punycode is kept as given; non-ASCII is invalid. | 1 |
| `deny`, `allow` | Each entry covers the name and its subdomains. Allow wins over every list and over `deny`, at any depth. | 3 |
| Block set layout | Per table, one byte buffer of sorted names plus a `u32` end offset per name; lookup is a binary search per label suffix. | 3 |
| Blocked reply TTL | 2 seconds (Pi-hole's default), so a pause shows within seconds. | 6 |
| Single-label names | `localhost`: `127.0.0.1` / `::1`, TTL 3600, empty success for other types (RFC 6761). Any other: A and AAAA get NXDOMAIN, no records; every other type goes through block check, cache and forward (amended after the final review, for DNSSEC). The root name is forwarded. | 6 |
| Private reverse zones | NXDOMAIN for any type at or under `10`, `16.172`–`31.172`, `168.192`, `254.169`, `127` `.in-addr.arpa` and `d.f`, `8.e.f`, `9.e.f`, `a.e.f`, `b.e.f` `.ip6.arpa` (RFC 6303). | 6 |
| Malformed input | Under 12 bytes, or a response: dropped. Opcode not QUERY: NOTIMP. Unreadable body, or a question count other than 1: FORMERR. The last two are 12-byte headers. | 5 |
| Other classes and types | Class other than IN, AXFR, IXFR: REFUSED. Every other type, ANY and unknown ones included: block check, cache, forward. | 5 |
| EDNS(0) | A reply carries OPT only if the query did: payload 1232, version 0, DO echoed, no options. Client options are ignored and not forwarded. Version other than 0: BADVERS. | 5, 6 |
| UDP size limit | 512 bytes without OPT; with OPT the client's size held to 512–1232. Over it: TC set, question only. TCP: no limit. | 6 |
| Reply flags | RA set, RD copied, AA, AD and CD clear (nothing is validated here). | 6 |
| Upstream query | Client's spelling of the name, RD set, OPT payload 1232, DO copied from the client. The caller picks the ID and checks it and the source address; this crate checks the question. | 5, 11 |
| Upstream failure | The caller tries the next upstream, then sends `Pending::servfail`. A stale answer under one hour was already served when the query was decided, so none is left to serve. | 10 |
| Cache key | Lower-case name, type, DO bit. | 8 |
| Cache lifetime | Lowest answer TTL held to 30–86,400 s. Negative (NXDOMAIN, or NOERROR with no answer): lower of the SOA's TTL and MINIMUM, held to 30–3,600 s; without an SOA it is not cached (RFC 2308). Other rcodes, TC and bodies over 4,096 bytes are not cached. A TTL with the top bit set counts as 0. | 8 |
| TTL sent | Every record of a cached answer carries the entry's remaining lifetime; a stale one carries 30 s (RFC 8767). | 8, 11 |
| Stale | Expired less than 3,600 s ago. A refresh is asked for at most once per 10 s per entry. | 8 |
| Today | Day number of `unix_secs + offset`; a change in either direction resets it. | 9 |
| 24-hour count | Per name, 24 hourly buckets on the monotonic clock: the current hour and the 23 before it. 1,024 names tracked, least recently blocked evicted. | 9 |
| Query log | Name, type, outcome, wall time. No client address. Error replies and drops are neither logged nor counted. | 9, 10 |

## hickory-proto 0.26 facts

Checked against 0.26.3 on 2026-11-10; the API differs from older releases.

- `hickory_proto::op::Message` has public fields `metadata`, `queries`, `answers`, `authorities`, `additionals`, `edns: Option<Edns>`. `Message::from_vec(&[u8])`, `to_vec()`, `Message::new(id, MessageType, OpCode)`, `Message::response(id, OpCode)`, `truncate()` (keeps the header, question and OPT; sets TC).
- `metadata` fields: `id`, `message_type`, `op_code`, `authoritative`, `truncation`, `recursion_desired`, `recursion_available`, `authentic_data`, `checking_disabled`, `response_code`.
- `Query` and `Record` have public fields (`name`, `query_type`, `query_class`; `name`, `ttl`, `data`). `Record::from_rdata(name, ttl, rdata)`. `u16::from(RecordType)`. `Name::iter()` yields labels as `&[u8]`; `to_lowercase().to_ascii()` gives `example.com.`, escapes a dot inside a label as `\.`, and gives `.` for the root. `SOA` has a public `minimum`.
- `Edns::new()`, `set_max_payload`, `set_dnssec_ok`, `max_payload()`, `version()`, `flags().dnssec_ok`.
- `from_vec` accepts trailing bytes, two questions, and an all-zero header; the checks in Task 5 are ours. An OPT with version 1 parses.
- BADVERS encodes correctly (the high rcode bits go in the OPT), but hickory decodes value 16 as `BADSIG`; assert on bytes.
- Re-encoding the three captured answers reproduces them byte for byte.

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum RuleKind { Exact, Suffix }             // the name only; the name and every subdomain
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct ListStats { pub exact: usize, pub suffix: usize, pub non_blocking: usize, pub invalid: usize, pub unsupported: usize }
pub fn parse_list(text: &[u8], emit: impl FnMut(RuleKind, &str)) -> ListStats;   // emits normalised names
```

Lines are split at `\n`. A UTF-8 byte-order mark at the start of the text, a trailing `\r`, and surrounding ASCII whitespace are removed. Then the first matching rule applies:

| Line | Result |
|---|---|
| empty; starts with `#`, `!` or `[` | nothing |
| starts with `@@` | `unsupported` + 1 |
| starts with `\|\|`, ends with `^`, and the text between passes `normalize` | emit `Suffix`, `suffix` + 1. One label is accepted: it blocks a whole top-level domain. |
| starts with `\|\|`, ends with `^`, and the text between fails `normalize` | `unsupported` + 1 if that text contains any of `* ^ $ / \|`, else `invalid` + 1 |
| starts with `\|\|`, anything else (options after `^`, no `^`) | `unsupported` + 1 |
| otherwise: split at ASCII whitespace, stopping at the first token that starts with `#`; one token | `unsupported` + 1 |
| — two or more tokens: the first is the address; each further token is a name, counted once | address not `0.0.0.0`, `127.0.0.1` or `::` → `non_blocking`; name parses as an IP address, has one label, or is `localhost.localdomain` → `non_blocking`; fails `normalize` → `invalid`; else emit `Exact`, `exact` + 1 |

### Task 3: Block set

**Files:**
- Create: `crates/qb-dns/src/blockset.rs`
- Modify: `crates/qb-dns/src/lib.rs`

**Interfaces:**
- Consumes: `parse::{parse_list, ListStats, RuleKind}`, `name::normalize`, `testutil::Rng`.
- Produces:

```rust
#[derive(Debug, PartialEq, Eq)]
pub struct InvalidName(pub String);             // the entry as given
#[derive(Default)]
pub struct BlockSetBuilder { /* private */ }
impl BlockSetBuilder {
    pub fn new() -> Self;
    pub fn add_list(&mut self, text: &[u8]) -> ListStats;   // a whole list, or a chunk that ends at a line break
    pub fn deny(&mut self, name: &str) -> Result<(), InvalidName>;    // a suffix rule
    pub fn allow(&mut self, name: &str) -> Result<(), InvalidName>;
    pub fn heap_bytes(&self) -> usize;
    pub fn build(self) -> BlockSet;
}
#[derive(Default)]
pub struct BlockSet { /* private: exact, suffix, allow tables */ }
impl BlockSet {
    pub fn is_blocked(&self, name: &str) -> bool;   // `name` already normalised: lower case, no trailing dot
    pub fn exact_len(&self) -> usize;
    pub fn suffix_len(&self) -> usize;
    pub fn allow_len(&self) -> usize;
    pub fn heap_bytes(&self) -> usize;              // capacity of the buffers, in bytes
}
```

Each table is a private `NameTable { bytes: Vec<u8>, ends: Vec<u32> }`: names sorted bytewise, duplicates removed, concatenated; `ends[i]` is where name `i` ends. The builder appends names to an unsorted buffer with a `(start: u32, len: u8)` index; `build` sorts the index, drops duplicates and writes the final buffers with exact capacity. `is_blocked` walks the name and each parent (cut at every dot): if any of them is in `allow` the answer is false; otherwise it is true if the full name is in `exact` or any of them is in `suffix`.

The fixtures are hand-assembled to RFC 1035 §4.1 and RFC 6891 §6.1.2. `Q_PLAIN` (`example.com` A), `Q_AAAA_EDNS` (OPT, payload 1232) and `Q_DO` (A, DO set) are byte for byte what was sent to 9.9.9.9 on 2026-11-10, which answered each. `Q_MIXED` spells the name `EXample.coM`. `Q_DIG` has the layout `dig` sends by default: AD flag, OPT with payload 1232 and one 8-byte COOKIE option.

`parse_query`, in order:

1. Fewer than 12 bytes, or the QR bit set → `Drop`.
2. Opcode not 0 → `HeaderOnly` with rcode 4.
3. `Message::from_vec` fails, or the question count is not 1 → `HeaderOnly` with rcode 1.
4. OPT present with a version other than 0 → `Refuse(q, BADVERS)`.
5. Class not IN, or type 251 or 252 → `Refuse(q, Refused)`.
6. Otherwise `Ok(q)`.

A `HeaderOnly` reply is: bytes 0–1 the query's ID; byte 2 = `0x80 | (packet[2] & 0x79)` (QR, with the opcode and RD copied); byte 3 = `0x80 | rcode`; eight zero bytes. `upstream_query(id)` is: the given ID, flags `0x0100`, the client's question unchanged, and an OPT with payload 1232, version 0, DO as the client set it, no options.

`handle_query`: the first step that applies decides. Each decision made on a `Question` is recorded in `Stats` with `q.name()`, `q.qtype()` and `now`.

1. `parse_query`: `Drop` → `Action::Drop`; `HeaderOnly(h)` → `Reply(h)`; `Refuse(q, rcode)` → `Reply(error(&q, rcode))`. None of these is recorded.
2. `local(&q)` is `Some` → `Reply`, `Outcome::Local`.
3. Blocking is not paused (`paused_until` is `None`, or `now.mono_secs` has reached it), `q.block_key()` is `Some(k)`, and `is_blocked(k)` → `Reply(blocked(&q))`, `Outcome::Blocked`.
4. Cache `Fresh { body, ttl }` → `Reply(relay(&q, &decoded body, Some(ttl)))`, `Outcome::Cached`.
5. Cache `Stale { body, refresh }` → the reply is `relay(&q, &decoded body, Some(STALE_TTL))`; `ReplyAndRefresh` with a refresh `Pending` when `refresh`, else `Reply`; `Outcome::Stale`.
6. Otherwise `Forward(Pending)`, `Outcome::Forwarded`.

The cache key is `Key { name: q.name(), qtype: q.qtype(), dnssec_ok: q.dnssec_ok() }`. A cached body that fails to decode counts as a miss.

```rust
#[derive(Debug, PartialEq, Eq)]
pub enum UpstreamOutcome {
    Reply(Vec<u8>),    // send to the waiting client
    Refreshed,         // a refresh was taken in; nothing to send
    RetryOverTcp,      // the answer was truncated: ask the same upstream again over TCP
    Mismatch,          // not an answer to this question: ignore the packet and keep waiting
}
impl Resolver {
    pub fn handle_upstream(&mut self, pending: &Pending, packet: &[u8], via: Transport, now: Now) -> UpstreamOutcome;
}
```

`handle_upstream`, in order:

1. The packet does not decode, is not a response, or does not have exactly one question equal to the pending one (name compared without case, same type and class) → `Mismatch`.
2. TC set and `via` is `Udp` → `RetryOverTcp`.
3. Remove the OPT. If `lifetime` gives `Some(l)`, store the re-encoded message under the pending question's key at `now.mono_secs`.
4. A refresh → `Refreshed`. Otherwise `Reply(relay(&question, &message, ttl))`, where `ttl` is `Some(l)` if the answer was stored and `None` if not.

Nothing is recorded in `Stats` here: the query was recorded when it was forwarded.
