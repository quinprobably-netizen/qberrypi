# Milestone 0: first boot on the Pi

Date: 2026-11-10. Board: Raspberry Pi 3 Model B Plus Rev 1.4. Build 1794329091, deployed with `cargo xtask deploy` beside a running Raspberry Pi OS.

## Result

It worked on the first attempt. The Pi restarted into qberrypi, ran for 40 seconds, restarted by itself and came back as Raspberry Pi OS.

| Time after init started | Event |
|---|---|
| 0.000 s | Banner; clock set to the build time |
| 0.127 s | `config.txt: Restored` (the one-shot restore, before anything else) |
| 0.251 s | `rfkill`, `cfg80211`, `brcmutil`, `brcmfmac` inserted |
| 0.430 s | `wlan0` present; vendor sub-module `brcmfmac-cyw` loaded |
| 40.000 s | `returning`, then the restart |

- Init logged no warning and no error. The watchdog opened and the activity LED accepted its setting.
- The Wi-Fi driver asked the kernel's module helper for `brcmfmac-cyw` and qberrypi's own helper loaded it. The fallback of inserting it explicitly was not needed.
- The Wi-Fi chip's firmware loaded (BCM4345/6, version 7.45.265).
- The driver insert returned in about a tenth of a second, far inside the watchdog's 15 seconds.
- Init's restart reset the board: afterwards the firmware reported a watchdog-type reset, which is how this board restarts.
- The framebuffer console came up without the graphics overlay (`switching to colour frame buffer device`).
- The card's log has one boot header and does not contain the passphrase.

Back on Raspberry Pi OS: `config.txt` is byte-identical to the saved `config.pios.txt`, the staging directory is gone, the kernel reported no FAT problem on the boot partition, and the DNS service the Pi runs was answering again within about two minutes of the deploy starting.

## What QEMU could not show, now shown

- The firmware reads qberrypi's `config.txt`, applies `os_prefix=qberrypi/`, and loads the kernel, device tree and `initramfs8` from the folder.
- The watchdog is a real timer here: arming it does not reset the board.
- Init's own restart request resets the board.
- The Wi-Fi driver finds its chip and gets its sub-module through the helper.

## Unexpected

- While `cfg80211` was loading its regulatory certificates, the kernel asked the helper for `crypto-pkcs1(rsa,sha256)`, which is not in the module table. The signed regulatory database was therefore probably not verified, and the configured country may not have been applied. Milestone 1 has to add the signature-checking module, or show it is not needed, before Wi-Fi joins.

## Not measured

- Time from power-on to the banner. The log's timestamps start when init starts. Milestone 1 should put the kernel's own timestamp in the banner line.
- What the screen and the LED showed: not recorded.
