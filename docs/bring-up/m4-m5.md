# Milestones 4 and 5: resilience and the front panel on the Pi

Date: 2026-11-11. Board: Raspberry Pi 3 Model B Plus Rev 1.4. Every check below was a one-shot boot
deployed with `cargo xtask deploy`, with one provoked failure per boot (`debug.fault`).

## Resilience

| Check | How it was provoked | What happened |
|---|---|---|
| Crash loop | a supervised service that fails at once, every time | the supervisor backed off, the loop ended in a restart of the board, Raspberry Pi OS came back |
| Panic | a panic on the runtime thread | the board restarted; the card was intact |
| Stall | the runtime thread stopped feeding the hardware watchdog | the watchdog restarted the board after its 15 s |
| No association | a network name that does not exist | the LED blinked fast and the board restarted after 90 s without a link |
| Pulled power | the cord, while qberrypi was answering | the card was intact and the next boot was clean; nothing is written to the card in permanent mode |
| Lost link | `drop-link`: the interface is taken down under the running system | the link was back and answering 3 s later |
| Dead radio | `mute-probe`: the station probe's answers are thrown away | three missed probes declared the link lost at 83.7 s; the rejoin followed |

The spec's "restarted access point" was not done as written: the development PC shares that access
point. `drop-link` and `mute-probe` stand in for it, and cover both ways a link is lost (the kernel
says so, and the kernel does not). A 30-minute quiet-link run to rule out false triggers of the probe
is still open (see `deferred.md`).

The stall counters in `/api/v1/stats` (`stalls`) were added after a latency scare during the watchdog
build and showed no runtime-thread stall of 100 ms or more and no resolver lock held longer than
0.3 ms in any measured pass.

## Front panel

The 3.5-inch SPI touchscreen runs the "Drain" design: questions fall into a funnel, blocked ones drain
away, and the readings (board temperature, questions today, share blocked, clients) sit beside it.
The owner confirmed on the real screen:

- the panel draws at 8 frames a second from the blocking pool, writing only changed rows, with no
  effect on DNS latency (`latency-baseline.md`);
- the gate key pauses blocking, shows `OPEN m:ss` and resumes by itself;
- a real threat-list hit takes over the panel as an alert card, and a tap dismisses it;
- the states `JOINING WI-FI`, `LISTENING` and `QUIET n MIN` appear when they should.

Calibration of the touch layer is per board and lives in the private configuration.
