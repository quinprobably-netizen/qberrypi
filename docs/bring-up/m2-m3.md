# Milestones 2 and 3: resolver, clock and blocker on the Pi

Date: 2026-11-11. Board: Raspberry Pi 3 Model B Plus Rev 1.4. Build 1794384090 (commit 26083a4),
one one-shot boot of 240 s, deployed with `cargo xtask deploy` while `cargo xtask probe --stage blocker`
asked the Pi from the PC. The two milestones' Pi checks ran in this single boot, because the blocker
probe runs the resolver's eight checks first.

## Result

It worked on the first attempt. The probe printed `15 of 15 checks hold`:

- a forwarded name is answered
- a repeat is answered from the cache
- a cached repeat is faster
- a repeat's TTL has not grown
- a query over TCP is answered
- a single-label name is answered by the Pi
- the clock is set
- the upstream latency is known
- the snapshot is in force before any refresh
- the snapshot's marker is blocked
- a listed name gets 0.0.0.0
- a listed name gets :: for AAAA
- the lists are refreshed over HTTPS
- after the refresh the marker is gone and the listed name is still blocked
- blocked queries are counted

| Time after init started | Event |
|---|---|
| 0.192 s | CPU governor `performance` |
| 0.695 s | services started on the runtime |
| 1.269 s | snapshot loaded: 302,264 names in **572 ms** (budget 3 s; QEMU took 735 ms) |
| 1.271 s | DNS listening on port 53 (before Wi-Fi has joined) |
| 1.273 s | status server listening on port 80 |
| 3.762 s | Wi-Fi joined on 5 GHz |
| 3.789 s | address and default route set |
| 4.292 s | clock set by SNTP, stepped +127.5 s from the build time |
| 64.6 s | list 1: 2,378,843 bytes in 280 ms |
| 65.1 s | list 2: 5,098,884 bytes in 443 ms |
| 65.5 s | lists refreshed: 302,263 names from 2 lists in 1.3 s |

- The clock was set 0.5 s after the route was there. The refresh waited the planned 60 s after the clock.
- TLS without AES instructions (rustls with the pure-Rust `rustls-rustcrypto` provider, no `ring`) fetched 7.5 MB in 0.72 s, and parsing and building the block set added about 0.6 s.
- Sizes: the stripped executable is 3,242,440 bytes (the plan's 3 MB budget is exceeded by TLS and the snapshot decoder; ruled acceptable), `initramfs8` 4,135,127 bytes (budget 6 MB), `/blocklist.zst` about 1.84 MB.
- The log has no `WARN` or `ERROR` line, and no `dns: no upstream answers`, no `dns: upstream … does not answer` and no `clock: no time server answered` line. It holds neither the passphrase, nor a list URL, nor the probe's names.
- qberrypi answered 17 of 17 echo requests. Back on Raspberry Pi OS, `config.txt` is byte-identical to `config.pios.txt` and Pi-hole was listening and blocking.
